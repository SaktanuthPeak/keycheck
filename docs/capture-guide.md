## ส่วน A — สำหรับผู้ใช้เว็บ

### A.1 ข้อความสั้นสำหรับหน้า `/` (Spec §10.2, §17.2)

พร้อมคัดลอกไปใช้ใน Frontend (ข้อความต้องสอดคล้องกับ Error message ใน [`api-contract.md`](./api-contract.md) §3):

```text
ตรวจคีย์แคป A–Z บนคีย์บอร์ด QWERTY แถวเยื้องทั่วไป (อ่านเฉพาะตัวอักษรอังกฤษ)

วิธีถ่าย
1. วางคีย์บอร์ดบนพื้นเรียบ ถ่ายจากด้านบนให้กล้องขนานกับคีย์บอร์ดมากที่สุด
2. ให้ปุ่มตัวอักษร Q ถึง P และ Z ถึง M อยู่ในภาพครบ และเต็มภาพพอสมควร
3. ใช้แสงสม่ำเสมอ หลีกเลี่ยงเงาสะท้อนบนหน้าปุ่ม
4. เอามือ สายเคเบิล และสิ่งของออกจากบนคีย์บอร์ด
5. ถือกล้องให้นิ่ง ตรวจว่าภาพไม่เบลอก่อนส่ง

หลังอัปโหลด แตะกึ่งกลางปุ่ม 4 จุดตามลำดับ: ซ้ายบน → ขวาบน → ขวาล่าง → ซ้ายล่าง
(ปกติคือ Q → P → M → Z) — แตะตาม "ตำแหน่ง" ของช่อง ไม่ใช่ตามตัวอักษรที่เห็น
เพราะปุ่มอาจถูกสลับอยู่

รองรับไฟล์ JPEG/PNG ไม่เกิน 15 MB · ไม่รองรับ HEIC
```

### A.2 การแตะจุดอ้างอิง Q → P → M → Z (Spec §7.2, §10.4)

```text
แถวบน   [1]Q  W  E  R  T  Y  U  I  O  [2]P
แถวกลาง     A  S  D  F  G  H  J  K  L
แถวล่าง       [4]Z  X  C  V  B  N  [3]M
```

| ลำดับ | จุด | ตำแหน่ง (ไม่ใช่ตัวอักษรที่เห็น) | พิกัด Canonical (u) |
| ---: | --- | --- | --- |
| 1 | TL | ช่อง **ซ้ายสุด** ของแถวบนของตัวอักษร | (0, 0) |
| 2 | TR | ช่อง **ขวาสุด** ของแถวบน | (9, 0) |
| 3 | BR | ช่อง **ขวาสุด** ของแถวล่าง (ปุ่มตัวอักษรตัวสุดท้ายก่อน `,`) | (6.75, 2) |
| 4 | BL | ช่อง **ซ้ายสุด** ของแถวล่าง (ถัดจาก Shift ซ้าย; บน ISO มีปุ่มเพิ่มหนึ่งปุ่มคั่นระหว่าง Shift ซ้ายกับช่องนี้) | (0.75, 2) |

- แตะ **กึ่งกลางหน้าปุ่ม** ไม่ใช่มุมปุ่มหรือขอบคีย์บอร์ด
- ถ้าปุ่ม Q กับ P ถูกสลับกัน จุดที่ 1 ยังคือช่องซ้ายสุด (ซึ่งตอนนี้มีปุ่ม P อยู่)
- จุดสี่จุดเป็นสี่เหลี่ยมคางหมู (แถวล่างสั้นกว่าและเยื้องขวา) เป็นเรื่องปกติ
- แตะผิดได้ ใช้ Undo/Reset; เปลี่ยนภาพแล้วต้องแตะใหม่ทุกครั้ง

### A.3 สิ่งที่ทำให้ภาพถูกปฏิเสธหรือได้ผล "ไม่แน่ใจ"

| สิ่งที่เกิด | ผลในระบบ | วิธีแก้ |
| --- | --- | --- |
| ไฟล์ HEIC / ไม่ใช่ภาพ | `UNSUPPORTED_IMAGE` (415) | iPhone: ตั้งค่า > กล้อง > รูปแบบ > "เข้ากันได้มากที่สุด" หรือแปลงเป็น JPEG |
| ไฟล์เกิน 15 MiB หรือเกิน 24 MP | `IMAGE_TOO_LARGE` (413) | ลดความละเอียดกล้องลงหนึ่งระดับ |
| ไฟล์เสีย Decode ไม่ได้ | `IMAGE_DECODE_FAILED` (422) | ถ่ายใหม่ |
| จุดไม่ครบ 4, อยู่นอกภาพ, ไขว้กัน หรือสี่เหลี่ยมเล็กเกินไป | `INVALID_CORNERS` (422 ตอนส่ง) | แตะใหม่ตามลำดับ TL → TR → BR → BL; ถ่ายใกล้ขึ้น |
| แตะครบแต่วนกลับทิศ (เช่น Q → Z → M → P) | งาน `rejected` + `INVALID_CORNERS` (Worker ตรวจทิศ) | แตะใหม่ตามเข็มนาฬิกา: ซ้ายบน → ขวาบน → ขวาล่าง → ซ้ายล่าง |
| แตะตามเข็มนาฬิกาแต่ **เริ่มผิดมุม** (เช่น P → M → Z → Q) | **ไม่ถูกตรวจเป็น `INVALID_CORNERS`** — Detector: คาดว่าได้ `LAYOUT_MISMATCH`; Baseline: ได้ผลรายช่องที่ผิดโดยไม่ถูกปฏิเสธ | เริ่มที่ช่องซ้ายบน (Q) เสมอ ตรวจจุดบนภาพก่อนกดส่ง |
| แตะจุดเลื่อนไปหนึ่งช่อง / คีย์บอร์ด Ortholinear หรือ Split | `rejected` + `LAYOUT_MISMATCH` (Spec §7.8) | ตรวจจุดอ้างอิงใหม่ หรือคีย์บอร์ดรุ่นนี้ไม่รองรับ |
| ภาพเบลอ แสงจ้า/มืดเกิน | คำเตือน `image_quality_low` และช่องที่อ่านไม่ได้เป็น `uncertain` | ถ่ายใหม่ตาม A.1 |
| แสงสะท้อนหรือมือบังบางปุ่ม | ช่องนั้นเป็น `uncertain` (ไม่ประกาศว่าถูกทั้งหมด, Spec §9.3) | ถ่ายใหม่ |

> Baseline (Fixed crops) ไม่มี Detection จึงตรวจ `LAYOUT_MISMATCH` ไม่ได้ ผลจะมีคำเตือน `layout_fit_not_checked` — แตะจุดเลื่อนช่องหรือเริ่มผิดมุมอาจได้ผลผิดโดยไม่ถูกปฏิเสธ (Spec §7.8) การตรวจจุดอ้างอิงตาม [`api-contract.md`](./api-contract.md) §3 ครอบคลุมเฉพาะ ไม่ครบ / นอกภาพ / ไขว้ / เล็กเกิน และ Worker ตรวจทิศเพิ่ม แต่ไม่มีการตรวจว่าเริ่มที่มุมไหน

### B.2 เคล็ดลับมือถือ

- แตะโฟกัสที่กลางบล็อกตัวอักษร (ประมาณปุ่ม G/H) และล็อก AE/AF ถ้าทำได้
- ถือสองมือหรือใช้ขาตั้ง/วางข้อศอก; ใช้ Timer 2–3 วินาทีลดการสั่น
- ปิดโหมด Portrait/Beauty/HDR ที่แต่งภาพหนัก และปิด Live Photo
- iPhone: ตั้งรูปแบบเป็น "เข้ากันได้มากที่สุด" (JPEG) — Backend ไม่รับ HEIC (§10.3)
- เปิดเว็บผ่าน HTTPS หรือ `localhost` เท่านั้น กล้องในเบราว์เซอร์ใช้ไม่ได้บน HTTP ผ่าน IP LAN (§10.3 [S7])
- ถ้าเบราว์เซอร์ไม่ให้สิทธิ์กล้อง ใช้ "เลือกภาพ" แทนได้
- ไม่ถ่ายหน้าจอ Preview ไปส่ง ต้องใช้ไฟล์ภาพเต็ม (§10.3)

### B.3 Protocol หนึ่งรอบถ่าย (`capture_session_id`)

ก่อนเริ่ม:

- คีย์บอร์ดอยู่ใน [`data/keyboards.csv`](../data/keyboards.csv) และมี `role` แล้ว (D10: เลือก Unseen test / Held-out validation **ก่อนถ่ายจริง**) และไฟล์นี้ Commit แล้ว — `.gitignore` ยังไม่ยกเว้นไฟล์นี้ ให้ใช้ `git add -f data/keyboards.csv` ([`annotation-guide.md`](./annotation-guide.md) §5.2)
- มี Arrangement schedule ที่ Generate แล้ว (`python -m ai.data.keyboard_dataset schedule …` → `metadata/arrangements.csv`, [`annotation-guide.md`](./annotation-guide.md) §5.3) และพิมพ์รายการแถวที่ `keyboard_id` ตรงกับคีย์บอร์ดตัวนี้ออกมาใช้ระหว่างถ่าย

1. ตั้ง `capture_session_id` = `<keyboard_id>_<YYYYMMDD>_<nn>` และจดลง Capture log: `device`, `lighting`, สถานที่ (ไม่อยู่ในภาพ)
2. ถ่ายตามแถวใน Schedule ของคีย์บอร์ดนี้ทีละแถว: จัดปุ่มตามคอลัมน์ `instructions` (`-` = ถูกทั้งหมด, `Q<->W` = สลับ Q กับ W, `A->S->D->A` = วน 3 ปุ่ม) แล้วจด `arrangement_id` ของแถวนั้น (เช่น `arr_0042`) ลง Log **นอกภาพ** — ห้ามตั้ง ID เองหรือสลับคู่อื่นแทน โดยเฉพาะแถว `test_only = 1` ซึ่งสงวนไว้ให้ Test (P2.A)
3. ระหว่างถ่าย ถ้าทำแถวไหนไม่ได้ ให้ข้ามไปและจดใน `note` อย่าแก้ Schedule ด้วยมือ
4. ต่อหนึ่ง Arrangement ถ่ายตาม `planned_shots` (1–3 ภาพ; Burst/ภาพใกล้เคียงกันทั้งหมดอยู่ Split เดียวกัน §5.5) แล้ว **ขยับกล้องและคีย์บอร์ดจริง** ก่อน Arrangement ถัดไป (§5.3)
5. เปลี่ยนแสงอย่างน้อยหนึ่งครั้งต่อรอบ (เช่น ไฟห้อง → แสงหน้าต่าง)
6. จบรอบ: ประกอบกลับเป็นถูกทั้งหมดและตรวจด้วยตาทุกปุ่ม (คืนคีย์บอร์ดที่ยืมในสภาพเดิม)
7. ภายในวันเดียวกัน: Copy ไฟล์ต้นฉบับ, จับคู่ชื่อไฟล์กับ `arrangement_id` ใน Log, ลบ GPS ออกจาก EXIF (เก็บ Orientation ไว้จนกว่าจะ Normalize ตาม [`annotation-guide.md`](./annotation-guide.md) §1)

**Capture log (หนึ่งแถวต่อภาพ):** `file_name`, `capture_session_id`, `keyboard_id`, `arrangement_id`, `device`, `lighting`, `note` — ชื่อคอลัมน์ตรงกับ `metadata/images.csv` จึงคัดลอกเข้าไปได้ทันที `arrangement_id` + Schedule คือแหล่งของ `actual_label` ตั้งต้น (§5.4) และบันทึก Seed กับคำสั่งที่ใช้สร้าง Schedule ไว้ที่หัว Log

ค่า `lighting` (ตาม `schema.py`): `daylight` (แสงหน้าต่าง), `indoor_warm` (หลอดแสงเหลือง), `indoor_cool` (หลอด LED/ฟลูออเรสเซนต์แสงขาว), `mixed`, `low`, `flash` (ใช้เฉพาะชุด Robustness `glare`), `other`

คีย์บอร์ดห้องแล็บที่ถอดปุ่มไม่ได้: ถ่ายเฉพาะภาพถูกทั้งหมด ใช้ `source = own_capture_fixed` และ `arrangement_id` ของแถว `kind = correct` แถวแรกใน Schedule ([`annotation-guide.md`](./annotation-guide.md) §5.3)

| คีย์บอร์ดห้องแล็บ (ถอดปุ่มไม่ได้) | ภาพถูกทั้งหมดตามที่ได้รับอนุญาต | `source = own_capture_fixed`; ใช้ฝึก Detector และวัด False-alarm (§5.1) |

### B.5 ชุด Robustness (แยกจากชุดมาตรฐาน — Spec §5.2, §7.8, §9.1, §9.2; Plan P2.B)

ถ่ายแยก `capture_session_id` ติด `subset = robustness` ใน `metadata/images.csv` และเขียนชนิดไว้ต้น `note` เป็น `robustness=<ชนิด>` (เช่น `robustness=glare`) ห้ามปนกับชุดมาตรฐาน (`subset = main`) ที่มีคำตอบครบ ตาราง GT 26 แถวยังต้องกรอกตามปกติ ([`annotation-guide.md`](./annotation-guide.md) §4)

| ชนิด | วิธีสร้าง | ผลที่คาด (Spec §17.1) | วัดด้วย |
| --- | --- | --- | --- |
| `blur` | ขยับมือระหว่างถ่าย หรือปิดโฟกัสอัตโนมัติแล้วโฟกัสผิด | คำเตือน `image_quality_low`, ช่องอ่านไม่ได้เป็น `uncertain` | Uncertain rate, ช่องที่ GT อ่านไม่ได้ |
| `glare` | ไฟส่องตรงบนปุ่มเงา หรือแฟลช (`lighting = flash`) | ช่องที่โดนสะท้อนเป็น `uncertain` ไม่ใช่ `incorrect` | FP ในภาพถูกทั้งหมด |
| `occlusion` | นิ้ว ปากกา หรือกระดาษเปล่าบัง 1–3 ปุ่ม | ช่องที่ถูกบังเป็น `uncertain` | Uncertain rate, False-alarm |
| `partial` | บางปุ่ม A–Z ถูกขอบภาพตัดบางส่วน **แต่กึ่งกลางช่อง Q/P/M/Z ยังอยู่ในภาพ** | ช่องที่ถูกตัดเป็น `uncertain` | Uncertain rate |
| `ortholinear_split` | คีย์บอร์ด Ortholinear/Split แตะสี่จุดตามช่อง Q/P/M/Z | `rejected` + `LAYOUT_MISMATCH` | Rejection rate (§9.1) |
| `wrong_reference` | ไม่ถ่ายใหม่: สคริปต์ประเมินผลเลื่อนจุดอ้างอิงของภาพมาตรฐานไปหนึ่งช่อง (เช่น W/O/N/X) หรือหมุนมุมเริ่มต้น | `LAYOUT_MISMATCH` (Detector); Baseline ตรวจไม่ได้ | Rejection rate (§9.1) |
| `steep_angle` | มุมกล้องเกินค่าตั้งต้นใน B.1 | ใช้หาขอบเขตมุมที่ยอมรับได้ | Error ตามมุม (§16.4) |

**นโยบาย Split ของชุด Robustness** (ภาพชุดนี้ใช้ประเมินและตั้งเกณฑ์เท่านั้น ไม่ใช้ฝึก):

- ถ่ายภาพ Robustness **เฉพาะบนคีย์บอร์ด `role = unseen_test` หรือ `heldout_val`** Splitter บังคับ Split ตาม `role` อยู่แล้ว (`split.py` กฎข้อ 2–3) ภาพจึงไปอยู่ Test หรือ Validation ทั้งหมด และไม่หลุดเข้า Train หรือ Group split 70/15/15 ห้ามถ่ายชุดนี้บนคีย์บอร์ด `role = train`
- คีย์บอร์ด Ortholinear/Split ต้องมีแถวใน `data/keyboards.csv` (`form_factor` เช่น `ANSI-other` และเขียน `layout=ortholinear` หรือ `layout=split` ใน `note`) โดยกำหนด `role = unseen_test` ถ้ามีมากกว่าหนึ่งตัว ให้ตั้งหนึ่งตัวเป็น `heldout_val` สำหรับตั้งเกณฑ์
- ส่วนที่อยู่ Validation ใช้ตั้ง `fit_thresholds` และ Threshold อื่น (§7.8) ส่วนที่รายงานใน Model card §5.4 ต้องมาจาก Test เท่านั้น
- `wrong_reference` สร้างจากภาพ `subset = main` ที่อยู่ใน Split เดียวกับที่ใช้วัด คือภาพ Test สำหรับรายงาน และภาพ Validation สำหรับตั้งเกณฑ์ ชุดนี้สร้างตอนประเมินผลเท่านั้น ไม่เพิ่มเป็นแถวใน `images.csv` และรายงานแยกเป็นชุดของตัวเอง
- ถ้ากึ่งกลางช่องอ้างอิงตกขอบภาพ ไม่ต้องเก็บเข้า Dataset (Validator ต้องการจุดครบสี่จุดในภาพ) กรณีนี้ทดสอบด้วย Unit test หรือ API test ว่าได้ `INVALID_CORNERS` (§16.1)
- ช่องที่ GT อ่านไม่ได้ (`readable = 0`) อยู่ในรายงาน Robustness เท่านั้น (§9.2)
- ชุด Robustness **ไม่ใช้อ้างว่าระบบตรวจปุ่มหาย** (§5.2)
